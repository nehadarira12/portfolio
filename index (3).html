Case study 01 · Healthcare · Voice AI

Launch testing for a voice agent that calls pharmacy patients

A US specialty pharmacy built an AI voice agent that phones patients to confirm their copay and pick a delivery date. A wrong answer here means a missed medication or a billing problem, so the agent had to be proven safe before it went live. I led the QA for it.

Voice AIHamming AIPythonCI/CDUAT
Scope
  • Copay confirmation call flow
  • Delivery date selection call flow
  • Real patient behaviour: unclear answers, interruptions, voicemail
How I tested
  • Built 400+ test cases in Hamming AI
  • Wrote a Python generator that creates test calls at full patient-list scale
  • Ran the tests inside the CI/CD pipeline on every change
What I delivered
  • UAT go/no-go report for the launch decision
  • Clear list of what was safe for version 1 and what was not
  • A repeatable test suite for later releases
Key results
FOUND

Interruption handling (barge-in) was not ready for real patients, so it was turned off for version 1.

FOUND

Voicemail detection broke in the phone layer, so voicemail handling was turned off for launch instead of risking wrong messages.

SHIPPED

My UAT go/no-go report set out what was ready, what was not, and the known risks before launch.

Case study 02 · Enterprise SaaS · AI Agents

Testing an enterprise AI agent platform: documents, security and load

An enterprise AI platform lets companies run AI agents that read their own documents and data. Customers need to trust that an agent reads the real file, keeps private data safe and stays up under load. I tested it from three sides.

AI agentsRAGPrompt injectionLocustLangSmith
1 · Does the agent really read?
  • Built a test pack of about 20 files, each with a unique hidden marker
  • Planted false claims in files to tell real reading apart from guessing
  • Tested search, page 87 of a 120-page PDF, tables, scanned PDFs and two-column text
2 · Is it safe?
  • Hid instructions inside documents to try to take over the agent
  • Checked how the agent handles personal data in summaries
  • Tested a new customer support portal before its launch
3 · Does it hold up?
  • Load tested the AI chat agent with Locust in Python
  • Included streaming responses and checks that answers stay correct
  • Raised the user count step by step to find the breaking point
Key results
PASSED

The agent treated hidden instructions in documents as content, not commands. It held back raw personal data unless a user gave a valid task reason.

FOUND

Found the point where the chat agent started failing under many users, and traced it to a backend limit so the team could fix the real cause.

FOUND

Filed 20+ bugs in the support portal across tickets, health monitoring and integrations before customers saw it. Also found screen labels that told users the wrong thing about which files were processed.
